# React 19 Suspense for Data Fetching — noviapet-web Reference

React 19 extends Suspense to **data fetching** via the `use()` hook. noviapet-web already uses
Suspense for code splitting; this reference covers the data-fetching variant for features like the
AI intake chat and ai_triage panel.

> **Status:** Suspense for data is stable in React 19.2 for the `use()` + promise pattern. For
> production caching/retry, prefer wrapping `apiFetch` calls in a memoized promise or a small
> data hook — `use()` itself does not cache.

## What changed vs React 18

React 18 Suspense supported only **code splitting** (lazy components). React 19 adds first-class
suspension on promises via `use()`:

```tsx
import { use, Suspense } from 'react';
import { apiFetch } from '@/lib/api-client';

function TriageSummary({ appointmentId }: { appointmentId: string }) {
  const triage = use(apiFetch<AiTriage>(`/api/appointments/${appointmentId}/triage`));
  return <UrgencyBadge urgency={triage.urgency_level} />;
}

function AppointmentPage({ appointmentId }: { appointmentId: string }) {
  return (
    <Suspense fallback={<Loading label={t('intake:generatingTriage')} />}>
      <TriageSummary appointmentId={appointmentId} />
    </Suspense>
  );
}
```

## Pattern 1 — Memoized promise (recommended for `apiFetch`)

A bare `use(apiFetch(...))` recreates the promise every render. Memoize it:

```tsx
function TriageSummary({ appointmentId }: { appointmentId: string }) {
  const triagePromise = useMemo(
    () => apiFetch<AiTriage>(`/api/appointments/${appointmentId}/triage`),
    [appointmentId],
  );
  const triage = use(triagePromise);
  return <UrgencyBadge urgency={triage.urgency_level} />;
}
```

> **React Compiler note:** the compiler auto-memoizes the promise in production, so `useMemo` is
> optional there. In **tests** (compiler disabled), `useMemo` is required to avoid re-creating the
> promise each render and causing infinite suspend loops.

## Pattern 2 — Polling a background job (ai_triage)

The ai_triage report is generated by a backend queue job (Laravel Horizon). The frontend must poll
until the job completes. `use()` on a single promise is NOT suitable for polling — use a small
polling hook with `useTransition` instead:

```tsx
function useTriagePolling(appointmentId: string) {
  const [triage, setTriage] = useState<AiTriage | null>(null);
  const [isPending, startTransition] = useTransition();

  useEffect(() => {
    let cancelled = false;
    const poll = async () => {
      const result = await apiFetch<{ status: 'pending' | 'complete'; triage: AiTriage | null }>(
        `/api/appointments/${appointmentId}/triage`,
      );
      if (cancelled) return;
      if (result.status === 'complete' && result.triage) {
        startTransition(() => setTriage(result.triage!));
      } else {
        setTimeout(poll, 2000); // poll every 2s
      }
    };
    poll();
    return () => { cancelled = true; };
  }, [appointmentId]);

  return { triage, isPending };
}

function TriagePanel({ appointmentId }: { appointmentId: string }) {
  const { triage, isPending } = useTriagePolling(appointmentId);
  if (!triage) return <Loading label={t('intake:generatingTriage')} />;
  return <UrgencyBadge urgency={triage.urgency_level} />;
}
```

## Pattern 3 — Nested Suspense boundaries

Show partial UI while different data loads independently:

```tsx
function AppointmentPage({ appointmentId }: { appointmentId: string }) {
  return (
    <div>
      <Suspense fallback={<Loading label={t('intake:loadingAppointment')} />}>
        <AppointmentHeader appointmentId={appointmentId} />
      </Suspense>
      <Suspense fallback={<Loading label={t('intake:generatingTriage')} />}>
        <TriageSummary appointmentId={appointmentId} />
      </Suspense>
    </div>
  );
}
```

## Pattern 4 — Error boundary integration

```tsx
function Root() {
  return (
    <ErrorBoundary fallback={<ErrorScreen />}>
      <Suspense fallback={<Loading />}>
        <TriageSummary appointmentId={appointmentId} />
      </Suspense>
    </ErrorBoundary>
  );
}
```

> noviapet-web does not yet ship a reusable `ErrorBoundary` class component. If you build the
> intake/triage feature, add one to `src/components/error-boundary.tsx` (class component — error
> boundaries still require a class in React 19).

## Parallel vs sequential fetching

**Parallel** (fetch both at once — preferred):

```tsx
<Suspense fallback={<Loading />}>
  <AppointmentHeader appointmentId={id} />
  <TriageSummary appointmentId={id} />
</Suspense>
```

**Sequential** (second depends on first) — only when truly dependent:

```tsx
function Page({ appointmentId }: { appointmentId: string }) {
  const appointment = use(apiFetch<Appointment>(`/api/appointments/${appointmentId}`));
  return (
    <Suspense fallback={<Loading />}>
      <TriageSummary appointmentId={appointment.id} />
    </Suspense>
  );
}
```

## Important warnings

1. **No caching** — `use()` does not cache. For shared/cached data, wrap `apiFetch` in a memoized
   promise or introduce a data layer. noviapet-web currently has no React Query; existing hooks
   (`use-clients.ts`, `use-breeds.ts`) manage their own state + `AbortController`.
2. **Memoize promises** — without memoization the promise is recreated every render.
3. **SSR** — not applicable; noviapet-web is a client SPA.
4. **Tests** — the React Compiler is disabled in tests, so memoize promises explicitly with
   `useMemo` to avoid suspend loops.
